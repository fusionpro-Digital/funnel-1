# FusionPro

Marketing site built from the Fusion Pro Digital Figma prototype.

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # production build
npm start        # serve the production build
npx eslint src   # lint
```

## Stack

Next.js 16 (App Router, Turbopack) · TypeScript · Tailwind CSS v4 · shadcn/ui on Radix · Geist + Playfair Display via `next/font`.

## Layout

| Path | What's there |
|---|---|
| [src/content/site.ts](src/content/site.ts) | **Every string on the page.** Edit copy here, not in components. |
| [src/components/site/](src/components/site/) | One file per page section, in the order they render. |
| [src/components/site/primitives.tsx](src/components/site/primitives.tsx) | `Container`, `Section`, `Eyebrow`, `DisplayHeading`, `Lede`, `CtaButton`, `Logo`. |
| [src/app/globals.css](src/app/globals.css) | Theme tokens, the violet gradient text, marquee keyframes, reveal states. |
| [public/media/](public/media/) | Image assets — see the README there. |

`src/components/ui/` is generated by the shadcn CLI; prefer re-running the CLI over hand-editing it.

## Things worth knowing before you change something

**The site is dark-only.** The Figma has no light variant, so tokens are declared on bare `:root` with no `.dark` class and no `prefers-color-scheme` block. Adding a light theme means adding those blocks, not editing these values.

**Headings are two-part.** `DisplayHeading` takes a `lead` (bold grotesque) and an `accent` (italic serif in the violet gradient) and stacks them. The sizes were matched against the comps by measuring rendered text width — the accent is deliberately *smaller* than the lead (59px vs 63px at `lg`), which is what keeps lines like "The pieces around it aren't working together." on one line.

**Scroll reveal is CSS, not state.** `<Reveal>` renders `data-reveal="pending"`; an IntersectionObserver flips it to `"visible"`. The hidden style lives in `globals.css`, so the server HTML is complete and visible — a `<noscript>` block in the root layout un-hides everything when JS is off, and `prefers-reduced-motion` disables the effect entirely.

**Marquee rows render their list twice.** The `-50%` keyframe has to land on an identical frame or the loop visibly jumps. If you add or remove a gallery item, the duplication in `gallery-marquee.tsx` handles it automatically — just don't render the list once.

**CTAs all point at one constant.** `CTA_HREF` in `src/content/site.ts` is a placeholder Cal.com link. Set it to the real booking URL before launch.

## Not built, and why

- **No real images.** The Figma export was flat screenshots, so no assets came with it. Every image slot renders a labelled placeholder until files are added — see [public/media/README.md](public/media/README.md) for the slot list and expected aspect ratios.
- **Client logos are text.** Same reason; drop real marks in and set `clientLogos[].src`.
- **Testimonial videos don't play.** While `videoSrc` is `null` the play glyph is decorative rather than a dead button. Set `videoSrc` and the card renders a real `<video>` with working play/pause.
- **`/privacy` and `/terms` are stubs.** They exist so the footer links resolve; the copy needs to come from counsel.
- **Mobile is an interpretation.** The prototype only had desktop frames. Notably, service cards drop their image below the text under `sm` — at 390px a 44%-wide image starved the text column.
